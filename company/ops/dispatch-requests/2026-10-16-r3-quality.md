### R3a. The scope test asks "does the lesson render as it did on the server?", not "is its newest commit older than the server?"
Why R3's clause is wrong: every evaluator record links itself into the lesson's own `meta.json` (`evidence.qa`, `evidence.simulatedLearner`; `company qa-record` does this too), and fact-checkers write claim verdicts there. So any lesson that has been judged once looks newer than the server it was judged on, and a second run on the same SHA is blocked by the first run's paperwork. R3 also missed `src/app`, which the lesson page is rendered from. The "strict" test (every commit is an ancestor) does not fix this after the rebuild at 5b2fee7: the first record filed on the new server breaks it again. So **R3a is the rule from now on, on every SHA.** It is not a stopgap until the rebuild.

For a server built from `S` and a lesson directory `D = src/demos/<d>/<slug>`, a run may file a record for the lesson, and a record already filed stands, if and only if all three hold between `S` and the tip being judged (the current main for "does it still stand", the run's start for "may it run"):
1. **Lesson files.** `git diff --quiet S <tip> -- D ':!D/meta.json'` (Demo.tsx, data, every file except meta.json are byte-identical).
2. **meta.json: only record fields differ.** Record fields are `evidence.*`, and for each existing claim (matched by `id`) `status`, `note`, `checkedBy`, `checkedOn`. An evaluator may also append a claim with `status: unverified` (working agreement 2, "record an unrecorded claim as unverified"); its committer must not be the lesson's builder. **Everything else is lesson content**, even though it lives in meta.json: `title`, `hook`, `question`, `reveal`, `recall`, `version`, `brief`, and an existing claim's `text`, `support`, `source`. If any of those differ, the lesson waits for a rebuild.
3. **Shared files.** Every file in `git diff --name-only S <tip> -- src/kit src/components src/lib src/app public content next.config.* package-lock.json` must be (a) **outside the lesson's import closure** (static and dynamic imports, followed from every file in `D` through `@/` and relative paths), and (b) **not shell**: `src/kit/**`, `src/app/**` except `src/app/api/**`, and top-level `src/components/*.tsx` always fail, because every lesson renders through them. A change to `src/app/api/**` passes only if no lesson reads that route's response (today: `/api/events` is a fire-and-forget `navigator.sendBeacon` in `src/kit/progress.ts`, and the response is never read). A `package.json` change passes only if it touches nothing but `scripts`.
Mechanically: `bash company/reviews/org/2026-10-16-r3a-scope/check.sh <S> <D> [tip]` returns 0 for pass and 1 for fail, and prints the reason. The R3 SHA reads (start and end, `status --porcelain` empty, BUILT_FROM) are unchanged. W-1314 needs **no change to `qa-record`**: a record linking itself is a record field under (2). I would rather not touch the judge's tool (tools/company.mjs, protected) when a rule fixes it.
"Newest non-evidence commit on the lesson dir (+ kit/components/lib it imports)", which today's runs used, is **close to R3a but not equal to it**. It counts an FC verdict commit as "non-evidence", it ignores `src/app`, and it does not catch a commit that changes `title` and `evidence` together. Today none of those gaps fired (below), but from this ruling on, runs use R3a's wording.
