## 1. Plan (written before probing)

Question for each line: with the key `direction:code` that `moves` returns, is the literal sentence true for every card that gets the key, in "some lessons" sense, against the cards still to be shown (the `moves` frame R'/D')?

Readings I test (literal):
- "This lesson moved ahead of some lessons" = at least one passed card y in the frame (dy < dx, ry > rx). "Some lessons moved ahead of this one" = at least one y with dy > dx, ry < rx.
- "lessons that build on other lessons" (L1) = at least one passed card y with a non-empty prerequisite list whose prerequisite concept has a lesson in dims other than y. Stronger reading I also test: at least one passed card y for which the prerequisites code contributed.
- "This one builds on other lessons" (L2) = x has a prerequisite concept with a lesson in dims other than x.
- "You've finished {title}, which is on the same idea" (L3, L4, L5) = finishedOnConcept non-empty, its first slug is in history, not x, and its concept equals x's concept.
- "Some lessons that share an idea with a lesson you've finished moved ahead of this one" (L6) = at least one y that passed x (in the frame) whose concept has a finished lesson.
- "This lesson moved ahead of some lessons that share an idea with {title}, a lesson you've finished" (L7) = finishedOnPassedConcepts non-empty, first slug finished, and at least one passed card y has that slug's concept.

Method: (a) read the code and derive what each code's eligibility implies (contributing test T2 in `pairCodes`); (b) probe: own script over the pilot entries of the dims index (230 lessons) with seeded random histories (sizes 0 to most of the pilot, random times, repeated slugs, random `now`, random `shown` sets) plus constructed histories; for every moved card check each reading above; (c) L3: construct a firing history or argue it cannot fire; (d) R1: search for earlier:refresh with empty finishedOnConcept and argue from the terms.

## 3. Findings per line (mine, before reading the author's support)

Notation: value = A + q(R − A), where A = newGain·prereqFactor and R = refresh. In `pairCodes(u, l)` a swap "contributes" when it closes a positive part of the gap. Swaps: prereq = (1 − q_u)·newGain·(pf_u − pf_l); q = (q_u − q_l)(R_u − A_u); refresh = q_u(R_u − R_l). A card "has state" iff a lesson on its concept is in history (in dims). That is the same set `finishedOnConcept` filters, so **x.s defined ⇔ finishedOnConcept non-empty** (estimate lines 214-217, 245-265 vs moves 500-515). Ungraded v3: every domain uses the prior (q = 0.2064 for every card with no state). Every card with state has q ≥ 0.6516.

General: for every moved card, "moved ahead of some lessons" (earlier) and "some lessons moved ahead of this one" (later) hold by pigeonhole. If rx < dx in a permutation of the same frame, some y has dy < dx and ry > rx, and conversely. The probe confirms this (0 failures).

- **L1 earlier:prerequisites: VERIFIED.** prerequisites eligible ⇒ for some passed y, pf_x > pf_y ⇒ prod_y < 1 ⇒ y has a prerequisite concept c with pKnownAt(c) < 1. That holds only when c has a state or a lesson in dims (line 236). No self-prerequisites ⇒ that lesson is not y. So y "builds on other lessons". Probe: 0 failures in about 1.61M cards.
- **L2 later:prerequisites: VERIFIED.** Eligible ⇒ for some passer y, pf_y > pf_x ⇒ prod_x < 1 ⇒ x has a prerequisite concept with a lesson in dims other than x. Probe: 0 failures in about 1.57M cards.
- **L3 earlier:concept-known: VERIFIED (reachable; the sentence is true when it fires).** concept-known is produced only when x.s is defined (line 475) ⇒ finishedOnConcept non-empty. Its first slug is a history slug in dims on x's concept, and it is not x (finished slugs are not ranked). Reachability: see §4.
- **L4 later:concept-known: VERIFIED.** Same argument (movedHasState = x.s, line 536). Probe: 0 failures in 17,825 cards.
- **L5 earlier:refresh: VERIFIED.** True if finishedOnConcept is non-empty. R1 (empty) cannot occur: see §4. Probe: 0 failures in 6,277 cards.
- **L6 later:refresh: VERIFIED.** Claim: some passer y has a finished lesson on its concept. Proof: refresh contributes in pair (y, x) only if R_y > R_x. If y has no state, R_y = refreshPrior, so R_x < refreshPrior, so x has state. In that pair the q swap = (q_x − 0.2064)(A_y − 0.00825) ≥ 0.117. The refresh swap is at most 0.2064·(0.00825 − R_x) ≤ 0.0017 when no completion is in the future, and below 0.07 even with future-dated completions (R_x ≥ kappa(14, mult) − 1, mult ≥ 0.56). The prereq swap is at most 0.038. So that pair's decisive code is q → concept-known. A pair with no state on either side gives decisive prerequisites (q and refresh swaps are exactly 0). So refresh earns decisive counts only from passers with state. If no passer has state, concept-known (earlier in CODE_ORDER) is eligible with at least 1 decisive and refresh has 0, so refresh is not chosen. Hence later:refresh ⇒ some passer has state ⇒ its concept has a finished lesson (not the passer itself). Probe: 0 failures in 833 + 1,012 cards. I first had the q-swap sign backwards and expected L6 to fail; the constructed test (l6.mts) and this derivation corrected it.
- **L7 earlier:passed-known: VERIFIED.** passedConcepts collects l.d.concept only for passed pairs where passed-known contributed (line 538), which needs finishedConcepts.has(l.d.concept) (line 535). So finishedOnPassedConcepts is non-empty, its first slug is finished, and some passed card y shares its concept. y ≠ title (y is not finished). Probe: 0 failures in 2,278 + 1,341 cards.

## 4. L3 and R1

**L3 fires.** Mechanism: x and l are uncompleted lessons whose twins are finished, l is ahead of x in the default order, and l's concept state has a higher q than x's. That happens when l's twin was finished more than once, or was finished with its prerequisites better known; 3,030 instances in l3b have no repeated slug. Both refreshes are small (recent finishes). Then x outranks l, q(x) < q(l) and R < A give a positive q swap that beats the refresh and prerequisite swaps, so concept-known is decisive. passed-known is also eligible, but concept-known wins on CODE_ORDER at an equal decisive count. The catch: x must still be earlier against the whole frame. Every card with no state sits at value ≈ 0.26 above recently stated cards, so this needs a frame of a few cards. Seen in frames of 2 to 11, reached through a large `shown` set or a history that covers nearly the whole pilot. Minimal reproduction (l3.mts, first instance): history = bad-hash-one-bucket and bet-too-much-and-go-broke (twice), all at now − 43 s, `shown` = every other unfinished pilot lesson. Result: hash-bucket-pileup → earlier:concept-known, finishedOnConcept = [bad-hash-one-bucket], passed card plus-fifty-minus-forty. It never fired in 3.24M cards from 78,000 natural histories (probe.mts, l3c.mts). Conclusion: reachable, rare, confined to small frames. The line is true on every instance found, and true by construction (§3).

**R1 (earlier:refresh with empty finishedOnConcept) cannot fire.** If x has no state, R_x = refreshPrior and q_x = 0.2064. The refresh swap is positive only against a passed l with R_l < refreshPrior, which needs l to have state, so l's concept has a finished lesson, so passed-known can apply (earlier). In that pair the q swap = (q_l − 0.2064)(A_x − 0.00825) ≥ 0.117. That beats the refresh swap (≤ 0.0017; < 0.07 with future-dated completions) and the prereq swap (≤ 0.038), so the pair is decisive for passed-known. Pairs with no state on either side are decisive for prerequisites. So refresh has 0 decisive counts while passed-known has at least 1, and refresh is never chosen for a card with no state. Probe: 0 of 6,277 earlier:refresh cards had an empty title, including future-dated and repeated histories. The argument uses only P's constants and the prior, not the pilot catalogue. If a graded estimate (domain posteriors) returns, it must be re-derived, because q for cards with no state would then differ by domain.
