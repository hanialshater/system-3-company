## 3. Independence (proposal §2) in this batch

**The builder is blind to the judge.** The reachable-signal oracle is the eval's code (`harness/c3/reachable-oracle.mjs`). The candidate is an independent build from the eval's **written** design, not a port of that file:
- **C1 reads only:** criterion 3 at 709ca2d, §1.1, §1.2, §2.2 and §4 (text); criterion 2 §I.3 and §I.4 (the input object and signature), §1.1 to §1.3 (the world's form) and §4 (the E1 table); E1 and E3 evidence files; A1's sheet; `model/model.ts` types (`HistoryItem`, `LessonDims`, `FORBIDDEN_INPUTS`); `src/kit/progress.ts` (the product's local record). Read with `git show 709ca2d:<path>` so nothing later leaks in.
- **C1 never opens, imports, copies or runs:** anything under `company/personalization/eval/harness/` (c2, c3, root, records), readouts 1, 2, 3 and their reproduction files, or any simulator. It runs **no** simulated episode of any world. It tests on hand-made histories only.
- **C1 writes a build note** (`company/personalization/policies/reachable-v1-build-note.md`): every file it read, and every point where §2.2's text left a choice, with the choice and why, written before the freeze.
- **No free constant.** Every number the candidate holds is either named in §2.2 (the 14-day valuation horizon, the +6.5-day assumed age) or comes from A1's sheet with its E1/E3 row. A1 reads the same text set as C1 and also may not open the harness. The candidate holds **base** values only, not per-cell values: in the sweep cells it is misspecified, as a shipped rule would be, which the oracle was not.
- **How independence is checked, not assumed:** K5 writes into criterion 3b, **before it reads C1's file**, an import check (the candidate imports nothing) and a copy check against `reachable-oracle.mjs` with its threshold (for example, shared comment text or a shared run of identifiers beyond §2.2's vocabulary). K6 runs both. A copy finding makes the candidate INVALID (rule G4 below). F5 reads C1's code against §2.2's text, not against the eval's file.
- **The limit, stated now:** the candidate is designed from the judge's own equations and scored in the judge's world. A no-harm result shows that a faithful, blind build of the written design does not hurt simulated learners in that world. It is not evidence about real learners, and §4 G7 says what copy may and may not say because of it.

**The judge is the eval's alone.** I write no line of criterion 3b, no cell, seed or rule. My asks in K5 are requirements it may refuse in writing with a reason. **Reproduction** (R4) is learner-model-engineer per proposal §2.5, in a fresh run that did not build C1: a byte comparison, no judgement.

## 4. Go/no-go rules for G, written before any score (pre-commitments, batch 5)

Written now, before C1 exists, before criterion 3b exists, and before any candidate number. I do not reopen them after K6. "Harm", "win", the interval and the guardrails are criterion 2 §2.1 and §3 as criterion 3b carries them (δ_harm = 0.01, δ_min = 0.01, 95% t interval over paired seeds; ordering guardrails G1 to G4).

- **G1. The gate is no-harm, not a win.** GO on the evidence requires, for `reachable-v1 + fixed` vs `default-order + fixed`, in **criterion 3b's base cell** (whichever it names at freeze; criterion 3 named `interleave:base`) **and in `first:base`** if 3b reports it (criterion 3 §2.0 calls it the closer cell for today's feed and a returning learner): (a) **no persona harmed** (no Δ_p ≤ −0.01 with the interval's upper end below 0), and (b) **every ordering guardrail G1 to G4 holds in every persona**. Fail either, in either cell: **NO-GO** for the website part of M1. Requiring `first:base` is stricter than M1's text; I add it because the shipped feed for a returning learner is closer to it.
- **G2. Wins are reported, not required.** I state the win count in the base cell as measured. Fewer than 4 of 6 wins does not block GO; it changes what may be said (G7).
- **G3. Sensitivity cells are reported, not gating.** Harms or guardrail breaks in one-at-a-time, outer or corner cells do not block GO. Every such cell is named in G's record and in the release note, word for word from readout 3b.
- **G4. INVALID is NO-GO.** If any validity check criterion 3b defines for the candidate fails (replay, frozen input, forbidden-input invariance, no state between calls, the import or copy check, a hash mismatch), the result is INVALID and G is NO-GO.
- **G5. No GO without a byte-identical reproduction.** If R4 finds a difference that changes any reading, I wait for the eval's corrected readout; I read only that.
- **G6. One candidate, no re-tuning.** After K6's first scored number, `reachable-v1` does not change. On NO-GO the website part of M1 is not met with v1, and I put to the chief of staff (founder's delegate) in writing: (a) M1 with HQ only and the website switch absent, or (b) a new candidate from a **new written design** (not new constants for the old one), built blind, frozen and scored under a new criterion; v1's result stays the record. I recommend (a) unless the NO-GO came from one guardrail with a named, design-level cause.
- **G7. Honest copy.** Reason copy says why a card is placed (the rule that fired, AMD-008 P3), never that personalization helps the learner remember more: a simulated result is not a fact about a learner. The release note and the opt-in's help line state readout 3b's base-cell result with "in our simulation" and its thinness (for example "no measurable gain" if wins < 4 of 6, and the three cells where readout 3's reference arm gained nothing). If G2 shows wins ≥ 4 of 6, the note may say "a small simulated gain", with the number.
- **G8. GO is the evidence gate only.** It does not by itself meet M1: §5's checklist and §7's objections still stand. Engagement is never a GO input.
