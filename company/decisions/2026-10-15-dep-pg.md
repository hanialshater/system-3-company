## Context
F-01 picked Postgres on Neon through the Vercel Marketplace. Better Auth needs a database connection (its built-in Kysely adapter accepts a `pg` `Pool`), and our own tables (progress, recalls, deletion) need one driver and plain SQL. `@vercel/postgres` is deprecated (checked 10-15 in f01-options.md).

## Options considered
| Option | For | Against |
|---|---|---|
| **A. `pg` 8.23.1** | The standard driver for 15 years; small; works through Neon's PgBouncer (pooled `DATABASE_URL`) and direct (`DATABASE_URL_UNPOOLED`); Better Auth's Kysely adapter takes its `Pool` directly; `pg_dump`-friendly exit | TCP connections from serverless functions need a small pool and short idle timeouts (ADR-009) |
| B. `@neondatabase/serverless` (HTTP or WebSocket driver) | Built for serverless; no TCP pool | Ties the code to Neon's driver, so exit is harder; one more vendor package; Better Auth would need a different dialect |
| C. `postgres` (porsager) | Fast and small | Better Auth's built-in path is `pg`; a second dialect means more glue |
| D. An ORM (Drizzle, Prisma) | Typed queries, migration tooling | Large trees; a schema DSL in front of tables the privacy reviewer reads as SQL. Plain SQL is easier to review against the gate |

## Decision (proposed)
A. `pg` as a **runtime dependency, exact pin `8.23.1`**, no `pg-native`. Rules:
- Always pass `connectionString` explicitly. `pg` falls back to the `PGHOST`, `PGUSER` and `PGPASSWORD` variables that the Neon integration also creates, and we do not want that silent fallback.
- Runtime code uses `DATABASE_URL` (pooled). Only the migration script uses `DATABASE_URL_UNPOOLED` (env contract: [notes/2026-10-15-accounts-env-contract.md](../engineering/notes/2026-10-15-accounts-env-contract.md)).
- One module owns the pool (`src/lib/server/db.ts`): `max` 3, `idleTimeoutMillis` 10 s, TLS required. The spike measures cold-start connect time.
- Migrations are plain `.sql` files and a script of about 50 lines that uses `pg`, with no migration framework (ADR-009).
- `@types/pg` is **not** in this record. If the spike needs it, it gets its own line, as a devDependency, in a follow-up to this record.
