- **L1 holds.** Read against ruling lines 36 and 39. `ALLOWED_FETCH` is anchored at the `fetch(` call, takes only the literal route in one of three quote forms, allows a query after `?` only, and requires `,` or `)` right after the string. Other `/api` mentions fail unless followed by exactly the route. ## W-1718 (src/lib/hq-personalization-server.ts, route.ts, tests/hq/personalization.test.mjs)

- **N1 fixed.** Meta no longer touches `inFlight`; a cold cache spawns its own process, and concurrent misses on the same stamp share `metaInFlight`. The `finally` guards on `metaInFlight?.p === p`, so a newer meta is not cleared by an older one. The stamp is taken before the spawn, so the cached result is at least as new as its key; an older result finishing late overwrites the cache with an older stamp, which only costs one recompute. Bound: one run process plus one meta process per distinct model stamp, so at most two in normal use (the stamp changes only when a model file is edited). That relaxes "one simulator process at a time" to "one run plus one meta", and the header comment says so. Accepted.
- **N1 test is weaker than its claim (nit M6).** The test proves meta is not refused while a run is in flight. It does not exercise "concurrent misses join one": no test fires two cold metas and asserts `a === b`. Add that one-liner next time the file is touched.
- **N2 fixed.** `busy?: true` on the failure variant; route returns 429 with `Retry-After: 5` only when `out.busy`; other failures stay 422. The test deepEquals `busy: true` for the refused request and `busy === undefined` for a failed run. The client reads `j.error` on any non-ok (Personalization.tsx lines 184, 287), so the message still shows; it ignores `Retry-After`, which is fine for a manual lab. The `!out.ok &&` in the route is redundant after the `out.ok` return (type narrowing only); not worth a change.
- **N3 fixed.** Bad persona fails, then the next request succeeds: the lock is released after a failure. This is the test I asked for. It leans on `spawnSim` always resolving (my D1 finding), which is why `finally` is enough.
