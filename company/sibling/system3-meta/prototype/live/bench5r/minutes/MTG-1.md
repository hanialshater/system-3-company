## 1. The module split: what behaviour each of slots A-D owns, now (wave 1) and as later waves add references, functions, recalculation and cycles; which slot each builder owns
Round 1:
- dev-2: Split by pipeline stage so each later wave lands mostly in ONE slot. A = PARSER (formula text -> AST): tokenizer, precedence (cmp < & < +- < */ < ^ right-assoc, unary binds to the next atom so -2^2=4), number syntax (1.2.3 bad), strings, TRUE/FALSE, call syntax NAME(args) parsed now even though wave 1 has no functions (so #NAME? is an eval decision, not a parse failure), and from wave 2 cell refs/ranges plus refs(ast) listing referenced cells. B = VALUES: the value/error representation, cell-name validation/normalisation (A1..Z99, case-insensitive, no leading zero), literal parsing for set() (" -2.5 ", .5, 12abc stays text), coercions (toNumber with ""->0, bool->1/0, numeric text; toText; case-insensitive compare), round9 and display(). C = EVALUATOR: walks the AST over B values, operator semantics, error propagation (left error wins), non-finite -> #VALUE!, #DIV/0!, and the function table (wave 1: every call -> #NAME?; wave 2 functions are added here only). D = STORE + DEPENDENCY GRAPH: raw text/AST/value per cell, wave 1 just storage; wave 2-3 dependents, recalc order (topological), cycle detection. SHEET = thin glue: createSheet() wires B (names, literals, display), A, C, D. Ownership (balances wave-1 load and keeps related reasoning together): dev-1 owns A and D (structural: syntax and graph), dev-2 owns B and C (semantics: values and evaluation). SHEET owned by lead (or whoever ARCH names) since it only composes. Rationale: hidden tests fail by category; with this split a failing category maps to one owner.
- reviewer: Split by pipeline stage so each later wave lands in one or two slots, not all four. A = formula syntax (work/MOD-A/parse.mjs): tokenizer + precedence parser (comparison < & < +- < */ < ^ right-assoc; unary binds to the atom so -2^2=4; 1.2.3 and unbalanced parens = parse error), cell-name validation/canonicalisation (A1..Z99, case-insensitive, no leading zero); wave 2 adds ref/range/call nodes here only. B = value model (work/MOD-B/values.mjs): error values, literal-input parsing (" -2.5 ", .5, 7 -> number; "12abc","TRUE" -> text), coercion (""->0, bool->1/0, numeric text->number, else #VALUE!), every operator incl. case-insensitive string compare and & text forms, non-finite -> #VALUE!, round-to-9, display(). C = evaluator (work/MOD-C/eval.mjs): walks the AST, left operand first so left error wins, unknown call -> #NAME?; wave 2 functions live in C (functions.mjs beside it), refs resolved through a callback so C never sees storage. D = cell store + dependency graph (work/MOD-D/store.mjs): inputs, cached values, wave 2/3 dependents, recalculation order, cycle detection. In wave 1 D is thin: that is deliberate headroom, it absorbs waves 2-3. SHEET = wiring only (createSheet, throw on bad names). Builders: dev-1 owns A + C (they share the AST contract, one person avoids drift); dev-2 owns B + D. Lead owns SHEET. Reviewer checks each slot against SPEC5 examples and the ARCH contract, and names the owning slot on any failing category.
- dev-1: Split along the pipeline so each slot grows in exactly one wave and nobody edits another slot to add a feature. A = syntax (MOD-A/parse.mjs): tokenizer + precedence-climbing parser -> AST, cell-name validation/normalisation; from wave 1 it already parses calls NAME(args) (so =FOO(1) gives a call node -> #NAME?, not a syntax error), and wave 2 adds ref/range nodes here only, plus refs(ast) listing referenced cells. Slot D = work/MOD-D/graph.mjs (owner dev-2): dependency graph, recalc order, cycle detection; wave 1 is a working but trivial graph with the final interface.
