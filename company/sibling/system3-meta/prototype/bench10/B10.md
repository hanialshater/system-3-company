# Benchmark 10: compile SQLite (the full principled org, against one agent)

owner: vp-meta · date: 2026-10-24 · status: **design; predictions committed before any run** · founder: "Yes go with
SQLite first, design B10" (2026-10-24), and "victories happen after many many failures … if we just change our mind
based on data that is not innovation that is accounting" · design: [../PRINCIPLES.md](../../PRINCIPLES.md), all of it

## The thesis, and what this benchmark is for

**Thesis (held, not up for a vote on one result):** an organisation of agents beats a single agent on work that is
too big for one context and too long for one sitting, as human institutions beat individuals on such work. B8 and B9
did not test it: their task fit one context (Lua: about 350k tokens with the compiler), was bounded, and was refereed
by wall-clock time on a shared machine, which parallel workers disturb. Three lean org designs lost there, as the
proportion principle said they would.

B10 is the first test built to give an org its reason. It is one step of a programme: if the org loses, we change the
design and run again; the predictions say what we expect, so a loss tells us *what* to change.

## The task

Source: SQLite 3.53.4's amalgamation as vendored in the npm package better-sqlite3 13.0.3 (`deps/sqlite3/`; sqlite.org and GitHub are not reachable from the container; npm is).

Starting from B9 V's compiler (the fastest; passes W1-W7 and builds Lua), **make the compiler build SQLite 3.53.4**
(the amalgamation, `sqlite3.c`: 269,668 lines, 9.5 MB, about 2.7M tokens) and a provided driver (`sqlrun.c`: reads an
SQL script, runs it statement by statement, prints every row and every error in a fixed format), so that the
resulting `sqlrun` binary gives **exactly the same output as the gcc-built reference** on SQL scripts it has never
seen.

- **Why it gives the org its reason:** `sqlite3.c` alone is about 2.7 times a 1M-token context. No single session can
  hold it, the compiler and the failing cases at once; the work must be read selectively, split, and remembered. It
  is long (the compiler today stops at the first missing system header, at line 40,289, and has never seen most of
  what SQLite uses at scale: unions and bit-fields in hot structs, function-pointer tables, 64-bit arithmetic
  everywhere, varargs formatting, deep macro use). And it decomposes into areas that need stewards (preprocessor,
  declarations and types, expressions, codegen, the ABI, the runtime headers).
- **Provided, as for W7:** a minimal header set with glibc's x86-64 layouts for what SQLite's Unix build includes
  (fcntl, sys/stat, sys/mman, sys/time, unistd, utime and the rest), checked by building SQLite with gcc against
  *only* these headers (`-nostdinc`) and passing the visible corpus; the fixed compile options (`SQLITE_THREADSAFE=0`,
  `SQLITE_OMIT_LOAD_EXTENSION`, `SQLITE_OMIT_WAL`, `SQLITE_DEFAULT_MEMSTATUS=0`, no `__GNUC__` builtins assumed beyond
  what W7 allowed); `sqlrun.c`; the link line (`gcc sqlite3.s sqlrun.s -o sqlrun -lm`).
- **The SQL corpus:** a deterministic generator (in the harness, not in the agents' trees) writes scripts in twelve
  families: tables and constraints, insert/update/delete with conflicts, expressions and type affinity, numeric
  formatting (`printf`, `round`, floats), strings and Unicode (`upper`, `like`, `glob`, `instr`), aggregates and
  `GROUP BY`, joins (inner, left, cross), subqueries and `EXISTS`, recursive CTEs, window functions, JSON functions,
  indexes with `EXPLAIN QUERY PLAN`-free plans, transactions and savepoints, triggers and views, and error messages.
  No `random()`, no `'now'`. The **visible corpus** (seed A, 600 scripts) goes to the agents with expected outputs;
  the **hidden corpus** (seed B, 3,000 scripts) never leaves the judge, which reports only counts.

## The score (the referee)

- **Primary: hidden pass rate**, the fraction of the 3,000 hidden scripts whose output matches the reference exactly.
  A build that does not compile or link scores 0.
- **Gate:** W1-W7's hidden runners still pass (the compiler must not regress on C it already handled), and Lua still
  builds and passes its tests.
- **Milestones** (reported, not scored): preprocesses; parses; compiles; links; `select 1` runs; first family above 90%.
- **Secondary** (reported): `sqlite3.c`'s compile time against gcc -O0, and the built SQLite's speed on a fixed
  workload against gcc -O0's build.
- Correctness does not depend on wall-clock time, so **both arms run at once** (the B9 measurement problem is gone),
  with generous per-script timeouts (10× the reference's time, at least 5 s).

## The arms

Same model family, tools, rules, sandbox and caps for both: **$150 and 6 active hours each**; both start from the same
tree with the same task text; both may use the visible corpus, gcc as a reference (never as the compiler) and the
fast judge.

**V, one agent.** One Agent SDK session (the SDK compacts its context when it fills), told the whole task, in charge
of its own plan. Continued with "go on" turns until the budget or time runs out, as B8 V.

**O, the full principled org** (PRINCIPLES.md, nothing left out that B9c left out):

| Element | How |
|---|---|
| Autonomy (1) | nobody assigns work; each member reads what it chooses, plans its own focus, changes course on evidence |
| Diversity (2) | 4 workers with generic temperaments (measure, bold, sceptic, lean); **each builds its own context** (no shared parent session, so no single witness); one of the four on a second model (Sonnet 5.5) as another source |
| Full context (3) | each worker's session persists across all rounds (warm); the SDK compacts it when needed; it starts by reading the compiler whole (about 90k tokens) and the parts of SQLite it chooses |
| Shared, organised learning (4) | the findings board (findings, dead ends, hypotheses; evidence and wrong-if required) organised by area, plus **practices with beliefs** (K38): a worker's hand-in names the practices it used; code updates each practice's belief from whether that worker's merge was kept and gained |
| Independent referee and credit (5) | after each round code merges the workers' heads into main one at a time (best first); a merge stays only if the gate passes and the hidden pass rate does not fall; credit = the rise in hidden pass rate; every result goes on the board |
| Roles and hierarchy | **architect** (fixed role, a warm session of its own): owns the interfaces between areas (the AST and type representations), resolves merge conflicts, settles disputed claims, sets each round's budget split, writes the round's intent ("the three families losing most"); assigns no work |
| Ownership as stewardship | **earned**: after round 2, the member with the most kept credit in an area becomes its steward (code decides, from the referee's record); a steward keeps `docs/areas/<area>.md` (its playbook), reviews every kept merge in its area in the next round and may ask the architect to revert it with evidence, and is still free to work anywhere |
| Coverage and reach | claims for short focus (as B9c); stewards give the floor; the coverage map per area (who looked, who changed, kept credit, reverts) is computed every round and shown to the architect |
| Proportion | 4 workers, not more; rounds stop when two rounds in a row gain under 1 point |

Rounds of 50 minutes; integration between rounds by code, the referee and (on conflicts) the architect. About 6-7
rounds in 6 hours.

## Predictions (committed before any run)

| # | Prediction | Wrong if | Prior |
|---|---|---|---|
| B10-1 | O's final hidden pass rate beats V's by at least 10 points | O − V < 10 points | 55% |
| B10-2 | V's context compacts at least twice, and V re-reads files it read before compaction (it cannot hold the problem) | fewer than 2 compactions | 80% |
| B10-3 | both arms reach `select 1` | either does not | 75% |
| B10-4 | O's pass rate rises in at least 4 of its rounds (the org keeps finding work), V's curve flattens earlier | O rises in fewer than 4 | 60% |
| B10-5 | stewards emerge in at least 3 areas, and a steward's review triggers at least one revert or fix | fewer | 50% |
| B10-6 | the referee reverts at least 2 merges (the org catches its own regressions) | fewer than 2 | 70% |
| B10-7 | the practice with the highest final belief is one about reducing a failing script to a minimal C case | another practice | 40% |
| B10-8 | O costs within 10% of V (both run to the cap) | outside | 70% |
| B10-9 | the Sonnet worker earns at least 15% of O's kept credit | less | 45% |

**If O loses**, the next design changes the most likely cause first, in this order: per-worker budget too thin; the
architect's intent too vague to spread the workers; stewards too late; the second model too weak. "A philosophy of
emergence should be willing to lose an A/B test", and willing to run the next one.

## What has to be built first (operator, before any run)

1. The header set, checked with gcc `-nostdinc` (SQLite builds and passes the visible corpus).
2. `sqlrun.c` and the reference build (gcc -O0, same headers and options).
3. The corpus generator; seeds A and B; reference outputs; a check that every script's reference output is stable
   across two runs.
4. The judge (fast: visible corpus, 600 scripts; full: hidden 3,000 plus the W1-W7 and Lua gates), sandboxed as B9's.
5. The O harness on B9c's code: persistent warm workers, the architect session, stewards by code, practice beliefs,
   the coverage map, the cost fix (time-capped turns estimated from transcripts).
6. A fake dry run of both arms, then a one-round real smoke test of O ($10 cap) to catch the harness's flaws before the
   real run (B9's harness flaws cost S a round and AO a round).

Estimated: preparation about 3-4 hours of operator work; the run 6 active hours (both arms at once); write-up 1 hour.
Cost: up to $300 for the two arms, plus about $10 for the smoke test.
