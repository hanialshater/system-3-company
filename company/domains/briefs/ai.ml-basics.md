### 58. best-of-twenty-on-one-test · concept: test-set-reuse · core · demand 3
- Format: Simulation run
- Audience and knowledge boundary: learner knows: why we hold out a test set (ten-test-cases), that a score is a sample (probability sample-size-noise) / does not know: that choosing the best of many models by the same test set turns that test set into training data, so the winner's score is inflated even when no model has any skill, and only a fresh test set shows it.
- Misconception: The top score on a leaderboard measures the top model's real skill; if no model is any good, no model will score well.
- Prediction (stage text, 23 words): "20 teams' models each just guess (50% chance per question). All are scored on the same 100 test questions. The best scores about:" options: A) 50% / B) 59% / C) 75% (answer: B). The locked stage shows 20 empty score bars and an empty "fresh test" bar; no 50% or 59% line is drawn.
- Check (node, 2026-10-14): exact expected maximum of m independent Binomial(100, 0.5) scores, E[max] = sum over k of 1 - F(k)^m: m = 1: 50.00, 5: 55.81, 20: 59.31, 100: 62.48. Simulation (mulberry32 seed 42, 20,000 leaderboards each): winner 50.00 / 55.80 / 59.30 / 62.47; the winner re-scored on a fresh 100 questions: 50.03 / 49.98 / 50.03 / 49.98. Example seeded run (seed 7, 20 models): scores 43,44,48,43,47,45,51,48,49,42,48,56,52,50,50,50,55,56,57,47; best 57; that model on a fresh test 46.
- What the stage shows: a leaderboard of 20 horizontal score bars (sorted after a run) with the winner highlighted; "Run leaderboard" scores all 20 on the shared test (seeded, seed shown, next seed each press); "Fresh test" re-scores only the winner on 100 new questions and draws its second bar beside the first. A models stepper (1, 5, 20, 100; at 100 the bars become a dot strip) changes how many compete. One readout line: "winner 57 · on fresh test 46". Controls: Run leaderboard, Fresh test, models stepper, Reset (4).
- Key state (milestones): question-run (a 20-model leaderboard run; winner score and seed recorded), fresh-scored (winner re-scored; fresh score recorded), crowd-seen (a run at 1 or 100 models; winner recorded). Reveal unlocks after question-run and fresh-scored.
- Reveal payoff (draft, 74 words): "No model knew anything, yet your winner scored 57 of 100. With 20 guessers, someone gets lucky on these 100 questions, and picking the best picks the luckiest. On fresh questions it fell to 46: the lead was noise. Using one test set to choose among many models quietly trains on it. The more models compete, the higher a skill-free winner climbs. Keep a final test set that is used once, after the choice."
- Phone fit (390x844): the reveal points at the winner's two bars and the readout line. 20 bars at 12 px each with 4 px gaps (about 320 px) is too tall with the reveal open: draw the leaderboard as 20 dots on one score axis (dot >= 12 px, winner ringed) with the fresh-test dot below it, so the picture is about 140 px. Stage-top crop 0 px with the axis, both winner dots and the readout visible when the reveal opens. The reveal's numbers come from the learner's own run (milestones above), not from the seed-7 example.
- Planned claims:
  1. With 20 models that each guess, scored on the same 100 questions, the best score averages about 59 (exact 59.31). support: derivation (expected maximum of 20 Binomial(100, 0.5)); source: node exact sum and seeded simulation (mulberry32, seed 42); fact-checker can re-derive with any binomial table.
  2. The winner's expected score on 100 fresh questions is 50, whatever it scored before. support: derivation (the fresh questions are independent of the choice).
  3. The expected winning score rises with the number of models: about 50, 56, 59 and 62 for 1, 5, 20 and 100. support: derivation; source: node.
  4. Reusing a test set to pick among many models inflates the reported score of the chosen model (adaptive overfitting); the remedy is a holdout used only once. support: citation; source: Dwork et al. (2015), "The reusable holdout: preserving validity in adaptive data analysis", Science 349(6248): 636-638; Hastie, Tibshirani and Friedman, The Elements of Statistical Learning, 2nd ed., section 7.2 (test set kept "in a vault"). About real systems.
- Curriculum (new concept): `{"id":"test-set-reuse","name":"Test-set reuse: the best of many models is flattered by luck","level":"core","demand":3,"prerequisites":["train-test-split"],"subarea":"ml-basics"}`; also probability:winners-curse, probability:multiple-comparisons; references none; tags evaluation, leaderboards, benchmarks.
- Differs from nearest: duplicates-in-the-test (data-leakage) leaks test items into training; here no item leaks, only the choice does. ten-test-cases (train-test-split) evaluates one model once. five-folds-five-scores (cross-validation) shows score spread for one model. The probability winners-curse and multiple-comparisons lessons have the same selection effect on auctions and p-values; this one adds the fresh-test re-score and the leaderboard setting, which those do not show.

### 68. squared-or-absolute-error · concept: loss-choice-mean-median · core · demand 2
- Format: Single card
- Strand: ml-basics
- Audience and knowledge boundary: learner knows: a model is fitted by making its total error small (linear-regression-fit, gradient-descent) / does not know: that the choice of error measure decides the answer: squared error is minimised by the mean, absolute error by the median, so one extreme value can drag a squared-error model far from most of the data.
- Misconception: Squared error and absolute error both find "the middle" of the data; the choice of loss is a technical detail.
- Prediction (stage text, 22 words): "A model predicts one delivery time for past deliveries of 2, 3, 3, 4 and 18 days. Minimising squared error, it predicts:" options: A) 3 days / B) 6 days / C) 18 days (answer: B). The locked stage shows the five dots on a 0-20 day line, no guess marker.
- Check (node, 2026-10-14): total squared error for guesses 0-18: 362, 307, 262, 227, 202, 187, 182 (at 6, minimum), 187, 202, ... 902. Total absolute error: 30, 25, 20, 17 (at 3, minimum), 18, 21, 24 (at 6), ... 60. Mean 30/5 = 6; median 3. Without the 18: data 2, 3, 3, 4, mean 3 and median 3.
- What the stage shows: a number line 0-20 with the five data dots, a guess marker, and thin error lines from each dot to the guess; below it a small loss curve (guess on x) that draws for the chosen loss. Preset buttons in DOM order: "Fit with squared error", "Fit with absolute error", "Remove the 18", Reset (4). Each fit sweeps guesses 0-18 instantly and drops the marker at the minimum. Readout: "squared error: best guess 6 (total 182)".
- Key state (milestones): squared-fit (guess 6, total 182 recorded), absolute-fit (guess 3, total 17 recorded), outlier-removed (both fits 3). Reveal unlocks after squared-fit and absolute-fit.
- Reveal payoff (draft, 73 words): "Squared error put the guess at 6 days, though four of five deliveries took 4 days or less. Squaring makes the 18-day delivery's miss count enormous, so the best guess moves toward it: the minimum of squared error is always the mean. Absolute error chose 3, the median, and barely noticed the 18. Remove it and both agree on 3. Choosing a loss is choosing which 'typical' you want the model to predict."
- Phone fit (390x844): the reveal points at the guess marker, the 18 dot and both loss minima. Number line 360 px wide (18 px per day), loss curve 360 x 100 px with the previous fit's curve kept faint; about 200 px total. Stage-top crop 0 px with line, curve and readout visible when the reveal opens.
- Planned claims:
  1. For 2, 3, 3, 4, 18, the total squared error is smallest at 6 (182) and the total absolute error at 3 (17). support: derivation; source: node sweep above.
  2. The constant that minimises total squared error is the mean; the one that minimises total absolute error is a median. support: derivation; source: Hastie, Tibshirani and Friedman, The Elements of Statistical Learning, 2nd ed., section 2.4 (squared loss gives the conditional mean, L1 loss the conditional median).
  3. Without the 18, the mean and the median are both 3. support: derivation.
- Curriculum (new concept): `{"id":"loss-choice-mean-median","name":"The loss chooses the answer: squared error gives the mean, absolute the median","level":"core","demand":2,"prerequisites":["linear-regression-fit"],"subarea":"ml-basics"}`; also math:mean-vs-median; references none (the work is not in content/works.json; it is cited in the claims); tags loss functions, outliers, regression.
- Differs from nearest: outlier-flattens-line (linear-regression-fit) shows one point moving a least-squares line; this one shows why (the squared loss itself) and offers the other loss as a choice. The math mean-vs-median lesson compares two summaries; this ties each summary to the loss a model is trained on.

### 69. colours-are-not-numbers · concept: categorical-encoding · core · demand 2
- Format: Before / after toggle
- Strand: ml-basics
- Audience and knowledge boundary: learner knows: a linear model fits a straight line to numeric inputs (linear-regression-fit) / does not know: that coding categories as 1, 2, 3 tells the model they are ordered and evenly spaced, so it can fit only patterns along that made-up order, and its answer changes when the codes are relabelled; one switch per category (one-hot) removes the fake order.
- Misconception: Turning categories into numbers like 1, 2, 3 is harmless; the model will work out what each one means.
- Prediction (stage text, 23 words): "Codes: red 1, green 2, blue 3. Green sells 30, red and blue 10. A straight line fitted to the code predicts green:" options: A) 30 / B) 17 / C) 10 (answer: B). The locked stage shows three colour bars of actual sales and empty prediction markers.
- Check (node, 2026-10-14): least-squares line on (1, 10), (2, 30), (3, 10): slope 0, predictions 16.67 for all (rounded 17), squared error 266.7. Codes green = 1, red = 2, blue = 3: predictions 26.67, 16.67, 6.67 (green, red, blue), squared error 66.7. One switch per colour: predictions 10, 30, 10, error 0.
- What the stage shows: three bars (actual sales) with a prediction marker on each and a small chart of the fitted line against the codes. Preset buttons in DOM order: "Fit on the code", "Recode: green = 1", "One switch per colour", Reset (4). After "One switch per colour" the code chart is replaced by three on/off switch columns (the before frame stays as faint markers). Readout: "green predicted 17 · total squared error 267".
- Key state (milestones): code-fit (17 for every colour, error 266.7 recorded), recoded (27 / 17 / 7, error 66.7 recorded), one-hot (30 / 10 / 10, error 0). Reveal unlocks after code-fit and one-hot.
- Reveal payoff (draft, 77 words): "With green coded as 2, between red and blue, a straight line could not rise for green and fall again: it went flat and predicted 17 for every colour. Recoding green as 1 changed the predictions to 27, 17 and 7, though nothing about the shirts changed. The numbers had invented an order. With one switch per colour, the model learned each colour's own sales: 30 for green, 10 for the others. Codes are names, not amounts."
- Phone fit (390x844): the reveal points at the three markers, the flat line and the switch columns. Three bars 80 px wide, code chart 360 x 110 px; about 230 px. Stage-top crop 0 px with bars, chart and readout visible when the reveal opens.
- Planned claims:
  1. The least-squares line through (1, 10), (2, 30), (3, 10) is flat at 16.67, so it predicts 17 (rounded) for green. support: derivation; source: node.
  2. With codes green 1, red 2, blue 3 the predictions become 26.67, 16.67 and 6.67. support: derivation.
  3. With one indicator per colour, a linear model fits each colour's mean exactly (30, 10, 10). support: derivation (each indicator's coefficient is that group's mean when there is no shared intercept).
  4. Coding an unordered category as a single integer imposes an order and spacing; indicator (dummy, one-hot) variables are the standard alternative. support: citation; source: Hastie, Tibshirani and Friedman, ESL 2nd ed., section 2.2 (qualitative variables represented by dummy variables); Kuhn and Johnson (2019), Feature Engineering and Selection, chapter 5.
- Curriculum (new concept): `{"id":"categorical-encoding","name":"Categories are not numbers: codes invent an order","level":"core","demand":2,"prerequisites":["linear-regression-fit"],"subarea":"ml-basics"}`; also none; references none; tags features, encoding, regression.
- Differs from nearest: income-in-dollars (feature-scaling) is about real numbers on different scales; here the numbers are not quantities at all. king-queen-arrow (embeddings) learns positions for words; this is the simplest fixed encoding and its trap.

### 70. widest-spread-hides-classes · concept: pca-ignores-labels · core · demand 2
- Format: Single card
- Strand: ml-basics
- Audience and knowledge boundary: learner knows: data points live in a space of features (curse-of-dimensionality, decision-boundary) / does not know: that principal component analysis keeps the directions where the data spreads most, chosen without looking at labels, so the direction that separates the classes can be the one it throws away.
- Misconception: Squashing data onto the direction where it varies most keeps the information that matters.
- Prediction (stage text, 21 words): "Squash these points to one number each, along the direction they spread most. Then the best single cut sorts the colours:" options: A) 100% right / B) about 75% right / C) 50% right, chance (answer: C). The locked stage shows the 16 points (circles and triangles) with no projection line.
- Check (node, 2026-10-14): 8 circles at y = +1 and 8 triangles at y = -1, x = -3.5, -2.5, ..., 3.5 in both. Variance along x 5.25, along y 1; share kept by x 84%. Best one-cut accuracy on the projection: widest (x) 50%; 45 degrees 62.5% (share kept 50%); narrowest (y) 100% (share kept 16%).
- What the stage shows: the 16 points, a projection line through the centre, each point dropped onto it with a thin tick, and a one-line strip below showing the squashed values with their shapes. Preset buttons in DOM order: "Keep widest direction", "Keep narrowest direction", "Keep 45 degrees", Reset (4). Readout: "spread kept 84% · best cut 50% right".
- Key state (milestones): widest-kept (84%, 50% recorded), narrowest-kept (16%, 100% recorded), diagonal-seen (50%, 62.5%). Reveal unlocks after widest-kept and narrowest-kept.
- Reveal payoff (draft, 75 words): "Along the widest direction the points kept 84% of their spread, but circles and triangles landed on exactly the same spots: the best cut was 50% right, a coin toss. The narrowest direction kept only 16% of the spread and sorted them perfectly. Principal component analysis ranks directions by spread and never looks at the labels, so it can discard the one difference you needed. Check what a compression keeps before you train on it."
- Phone fit (390x844): the reveal points at the projection line, the squashed strip and the readout. Scatter 360 x 160 px (points >= 12 px, shapes not colour alone), strip 30 px, readout; about 230 px. Stage-top crop 0 px with all three visible when the reveal opens; the widest-direction strip stays as a faint second strip after another preset.
- Planned claims:
  1. In the toy, the spread along x is 5.25 and along y is 1, so the widest direction (x) keeps 84% of the total spread. support: derivation; source: node.
  2. Projected onto x, the two classes have identical values, so no single cut beats 50%; projected onto y, a cut at 0 is 100% right. support: derivation.
  3. Principal components are the directions of largest variance, found without labels, and low-variance components can carry the information that predicts the target. support: citation; source: Jolliffe (1982), "A note on the use of principal components in regression", Journal of the Royal Statistical Society Series C (Applied Statistics) 31(3): 300-303; ESL 2nd ed., section 14.5.1.
- Curriculum (new concept): `{"id":"pca-ignores-labels","name":"PCA keeps spread, not meaning: the widest direction can hide the classes","level":"core","demand":2,"prerequisites":["decision-boundary"],"subarea":"ml-basics"}`; also none; references none; tags dimensionality reduction, PCA, features.
- Differs from nearest: near-the-wall (curse-of-dimensionality) is about too many dimensions; this is about which ones a reduction keeps. income-in-dollars (feature-scaling) shows a large-scale feature dominating distance; here both features are in the same units and the larger spread is still the wrong one.

### 72. near-coin-or-far-chest · concept: discount-factor · core · demand 2
- Format: Single card
- Strand: ml-basics
- Audience and knowledge boundary: learner knows: an agent learns to choose actions that earn reward (greedy-slot-machine) / does not know: that a reinforcement-learning agent counts future rewards at a discount set by its designer (gamma per step), so the same agent with a different gamma prefers a small near prize to a big far one, or the reverse.
- Misconception: An agent built to maximise reward will always go for the biggest prize.
- Prediction (stage text, 24 words): "A reward n steps away is worth 0.8^n of its size. Coin (1): 2 steps away. Chest (10): 20 steps. The agent goes to:" options: A) the chest / B) the coin / C) neither, it is a tie (answer: B). The locked stage shows the corridor: the coin 2 cells left of the agent, the chest 20 cells right; no values.
- Check (node, 2026-10-14): coin value gamma^2 x 1, chest gamma^20 x 10. gamma 0.8: 0.64 vs 0.115 -> coin. 0.88: 0.774 vs 0.776 (near the switch, which is at gamma = 0.1^(1/18) = 0.880). 0.9: 0.81 vs 1.22 -> chest. 0.95: 0.90 vs 3.58 -> chest.
- What the stage shows: a 23-cell corridor with the agent, coin and chest; above each prize, its discounted value bar; an arrow from the agent toward its choice and a short path trace. Preset buttons in DOM order: "Agent with 0.8", "Agent with 0.9", "Agent with 0.95", Reset (4). Readout: "gamma 0.8 · coin 0.64 · chest 0.12 -> coin".
- Key state (milestones): question-case (0.8; 0.64 and 0.12 recorded, coin chosen), switch-seen (0.9; 0.81 and 1.22 recorded, chest chosen), patient-seen (0.95). Reveal unlocks after question-case and switch-seen.
- Reveal payoff (draft, 68 words): "With 0.8 per step, the chest's 10 shrank to 0.12 over 20 steps, while the coin kept 0.64, so the agent took the coin. Nothing about the prizes changed when you set 0.9: the chest became worth 1.22 and the agent turned around. The discount is a design choice, not something the agent learns. It decides how short-sighted the agent is, and so which reward it will chase."
- Phone fit (390x844): the reveal points at the two value bars, the arrow and the readout. 23 cells at 15 px (345 px) in one row, value bars 80 px tall above; about 150 px. Stage-top crop 0 px with corridor, bars and readout visible when the reveal opens; the 0.8 choice stays as a faint arrow after another preset.
- Planned claims:
  1. With discount gamma per step, a reward R that is n steps away is worth gamma^n x R now. support: derivation; source: Sutton and Barto, Reinforcement Learning: An Introduction, 2nd ed. (2018), section 3.3 (discounted return, eq. 3.8).
  2. At gamma 0.8 the coin is worth 0.64 and the chest 0.12; at 0.9, 0.81 and 1.22; the preference switches at gamma = 0.88. support: derivation; source: node.
  3. The discount rate is a parameter chosen by the designer, not learned from reward. support: citation; source: Sutton and Barto (2018), section 3.3.
- Curriculum (new concept): `{"id":"discount-factor","name":"Discounting: how far ahead an agent cares","level":"core","demand":2,"prerequisites":["exploration-exploitation"],"subarea":"ml-basics"}`; also economics:present-value; references none (the work is not in content/works.json; it is cited in the claims); tags reinforcement learning, reward, agents.
- Differs from nearest: greedy-slot-machine (exploration-exploitation) is about trying unknown options; here everything is known and the choice turns on time. The economics present-value lesson discounts money; this shows a designer's number setting an agent's behaviour, the agent-design point that lesson does not make.
