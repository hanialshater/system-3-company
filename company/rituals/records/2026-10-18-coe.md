# Correction of Error: 2026-10-18: two unapproved production deploys from a deploy marker inside merge messages

owner: chief-of-staff (the role that wrote the messages) · reviewers: evaluation-steward, pattern-librarian

## What happened (facts, timestamps, links)

- 2026-10-18 15:25Z: the chief of staff merged PR #7 into the production branch `ccr-4c6c7654-ew9ko1` with the GitHub merge tool. The merge message (bcd102d7) ended with a sentence that negated the deploy marker but contained it literally ("No" followed by the bracketed word).
- 2026-10-18 16:42Z: same for PR #10 (merge 2902594b).
- `vercel.json` ignoreCommand builds any commit whose message contains the bracketed marker anywhere (`grep -qF`). Both merges built and deployed to production through Vercel's git integration; GitHub shows Vercel "Deployment has completed" on both commits.
- The deploy bypassed `tools/deploy.mjs` (no pinned `SHOW_REVIEW`, no deployment record, no release-log entry, no smoke test) and the founder's per-deploy approval.
- Found by the chief of staff at ~16:50Z while answering the founder's "is personalization in prod?"; reported at once. Founder: "Keep what’s live" (company/decisions/2026-10-18-founder-accepts-unapproved-deploys.md).

## Impact (learners affected, lessons, claims)

- Production moved from r10 (8eeb961a) to 2902594b without approval or a release record.
- Learner-facing: the feed order is unchanged (default order; the personalised order was never merged, its flag unset). Accounts still off (`/api/account/settings`, `/api/auth/session` 404). ## Five whys (stop when the answers stop being about people)
1. Why did production deploy? Both merge messages contained the bracketed marker, and the build filter matches it anywhere in the message.
2. Why did the messages contain it? The chief of staff wrote "No [marker]" as a reassurance, quoting the marker in a negation.
3. Why does a negation trigger a build? The filter is a substring match (`grep -qF`) on the whole message, so any mention of the marker, including a negation, a quotation or a description of the rule, deploys.
4. Why was nothing in the way? Merges to the production branch go through GitHub's merge tool, where no local hook runs; neither CI nor the merge tool checks a merge message for the marker against an approval.
5. Why is the marker a free-text word at all? Deploy intent was put in commit text (F-48, the switch to `[deploy]`-only builds) without a check that the text is deliberate; the same word appears dozens of times in records and rules, so writing it by accident is likely.

## What allowed it
The tool, gate, pattern or ritual that let it through. "Be more careful" is not an answer.

`vercel.json` ignoreCommand: a substring match for the marker anywhere in the commit message, with no tie to an approval record. Merges done through the GitHub merge tool, where no commit-msg hook runs.
