## Tier ruling

**Tier 2, not tier 1.** The engineering README puts "anything touching every lesson" in tier 2. The change
does not touch `src/kit/`, but it changes the reveal layout of all 509 lessons, which is the blast radius
tier 2 exists to cover. Merging before review was the right call because learners were blocked, and the
author's note works as an EDD and rollback plan. The process gap is that `npm run verify` was not run
on the integrated tree. A tier-2 merge made under urgency still owes that run afterwards (follow-up 1).

## Findings (problems, not fixes)

Correctness, checked against the diff:

- **Scroll math is correct and conservative.** It only scrolls down, by `min(overflow below, distance to the
  reveal's top − 12px)`, so a reveal taller than the card lands top-first. It does nothing when the reveal
  already fits, which covers desktop and tall phones. The `revealed` latch means it fires once per reveal and
  again only after a replay.
- **Reduced motion: compliant.** It sets `scrollTop` directly, which is instant and ignores `scroll-behavior`.
  The global reduced-motion rule disables reveal animations, so the 400 ms re-check just does nothing.
- **400 ms re-check can fight the learner.** If the learner swipes up to look at the stage within 400 ms of
  the tap, the timer scrolls them back down. This is minor and rare, but it is the only place the hook
  overrides a learner action.
- **Resize and orientation are not handled.** The fit is computed only at the moment of the reveal. If the
  phone is rotated to landscape (about 390px tall) after the reveal, the reveal goes back below the fold of
  an inner scroller that has no visible scrollbar. That is the original W-135 symptom again. Landscape was
  never measured, and the tool defaults to portrait 390×844.
- **Keyboard focus: an existing defect the fix does not address.** "Show me why" unmounts when it is clicked
  (`Lesson.tsx` swaps the panel), so focus falls back to `<body>` and nothing announces the reveal to a screen
  reader. The scroll helps sighted keyboard users but does not move focus. The fix belongs in the kit, which
  is a protected path and needs an amendment.
- **Feed vs single page.** `reveal-fit.mjs` measures `/d/<slug>` only. The feed uses the same DemoCard and
  geometry (100dvh card), but up to three observers run at once (active ±1). Nothing measures the reveal
  fit in the feed. The likely risk is low, but it has not been measured.
- **Observer cost.** The MutationObserver watches `childList` with `subtree: true`, so every React commit in an
  animating lesson runs one `querySelector` and one attribute read. That is cheap, but it runs on every frame
  for rAF-driven lessons. It is acceptable at this cost. If a frame-time budget is ever set, check this hook against it.
- **CSS override is safe as written.** All 115 `.stage-svg` module rules are the same pattern
  (`flex: 1 1 0; min-height; height: auto`), and every `.stage-svg` element I sampled has a `viewBox`. The
  global `max-height: 46dvh` still applies, so `height: auto` cannot grow a picture past the cap. The
  global rule's specificity beats the module rules, which is intended, but any future lesson that sets a
  deliberate fixed height on `.stage-svg` will have it overridden at the reveal.
- **The 6 thumbnail lessons** are caused by the lessons' own dvh caps (4 are confirmed, and in-order-is-sorted
  and the-fast-ones-leave need a check by eye). They are lesson-owned, not a defect in this change. The
  thumbnail heuristic has at least one probable false positive, so it should not be a gate yet.
- **The 7 unmeasured lessons** (exponential-growth, merge-sort-payoff, odd-numbers-make-squares, pendulum-period,
  push-the-swing-in-time, puck-on-ice-no-push, ramp-same-work) cannot be measured on the QA-contract path.
  Their reveal fit is unknown, not passed.

## Recommendation on reveal-fit as a gate (evaluation steward decides, by amendment)

Do not add `tools/reveal-fit.mjs` to `npm run verify` as it is. It needs a separate running build, adds a
second full pass over 509 lessons, and its thumbnail heuristic has false positives. Instead, add one assertion
to `tests/qa/contract.spec.ts` (protected), on the phone project only. After "Show me why", the bottom of the
reveal text must be inside the card body's visible rect, with no hard clip. The contract already reaches the
reveal for every lesson, so this costs almost nothing extra, and it makes W-135 a regression the gate
catches. Keep `reveal-fit.mjs` as a diagnostic, with the thumbnail measure reported but not gating, until
its false-positive rate is known.

## Decision

**Accept with follow-ups** (template: approve with changes). No revert. The fix is correct for the measured
case, one revert undoes it, and it unblocked learners. Objections that travel with it:

1. Tier 2 work merged without `npm run verify` on the integrated tree. Answer: accepted because of the
   urgency, on condition that follow-up 1 runs. If verify fails because of this change, revert.
2. Rotating after the reveal brings the W-135 symptom back. Answer: follow-up 2. It does not block
   acceptance, because portrait is the reported and measured case.
3. Focus is lost at the reveal (existing defect). Answer: follow-up 4. It needs a kit amendment.
