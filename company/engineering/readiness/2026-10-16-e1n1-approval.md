## Conditions

- **F1, before wiring the agent-events hook (tools-lead; it gates wiring, not the merge).** `fold` must not run twice at once. Take an exclusive lock in the spool dir (`fs.openSync(…, "wx")` holding the pid; refuse with a clear message when a live pid holds it, take it over when the pid is dead), and adopt a `*.folding-<pid>` file only when that pid is not running (`process.kill(pid, 0)` throws ESRCH). Add a test: two folds started together leave no duplicate id in the log. Why it gates: a duplicated line in events.jsonl is on my revoke list, and the fold is the only code that writes the log on the hook's behalf. Today only the chief of staff folds, so the chance is low. But the chief of staff runs several sessions, and nothing stops two of them.
- **F2, with F1 (tools-lead, not gating).** The author's race (1) is real (6 in 40,000 under a write rate many orders of magnitude above the hook's few writes an hour). Close it cheaply: after the renames, wait about 200 ms before reading (an in-flight `appendFileSync` finishes in well under that), or re-read each renamed file after the append and append any id not yet folded before removing it. A lost event is still in the transcript for the backfill, which is why this does not gate.
- **F3, the fold has one home (chief of staff).** The spool is shared by every checkout, but `fold` writes the events.jsonl of the checkout it runs in. Fold only in the integration worktree, as the ruling says, and never in the main checkout or a builder worktree. Add that line to company/ops/chief-of-staff-checklist.md next to the H2 ruling's fold step.
- **F4, the ruling's `company status` line (chief of staff).** See "Ruling H2" below. It does not gate the merge or wiring.
- **W2, added check (whoever applies F-31).** Besides the four W2 checks of 90fc0de, a commit whose message is a `$(cat <<'EOF' … EOF)` heredoc containing a line `git stash pop` is not refused. Record it on W-529.
- **Carried over unchanged:** H1, H3, H5, H6 (fee2b05); W1, W3, M1, M2, G1 to G5 (90fc0de). H3 now also covers spooled dispatches: they count as in flight for up to 6 h, the same as logged ones.
