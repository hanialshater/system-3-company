The founder approved unifying Map/List styling and making the existing World immersive and zoomable, then clarified that the World must branch rather than remain a linear corridor. This modifies existing World components/styles and navigation-only helpers; it adds no route, dependency, lesson contract, metadata/registry schema, account/event API or deployment configuration. Extending the read-only World presentation projection with existing concept identifiers/prerequisites is within this boundary. The ordered path map leaves these paths tier1. The prior World route introduction was tier2; that does not make every subsequent presentation edit tier2. See `company/engineering/README.md`, `readiness/paths.json` and `readiness/README.md`.

## Branching model: latest founder correction

Keep all162 existing island IDs, their lesson membership/player URLs and all3895 registered lessons. Prefer a manageable hierarchy: fourteen subject hubs in an atlas, subject-focused island clusters, then an island's3–5 region hubs with lesson leaves. Shared Map/List hierarchy and selection make these navigation/containment branches meaningful. Region-to-lesson spokes mean membership and choice, not manufactured prerequisite relationships; do not replace the former corridor with decorative fake forks.

Derive a separate sparse connection graph from actual `content/curriculum/*.json` prerequisite arrays and lesson concept IDs. Namespace a concept as `domain:concept`; an unqualified prerequisite belongs to its concept's domain. Map each concept to a **set** of island IDs, since one concept may have lessons in multiple islands (including Number Island). Resolve only actual concept/lesson mappings, expand valid island pairs, omit self edges, and deduplicate. Missing references produce no invented lesson or connector; retain them in diagnostics rather than silently teaching a made-up dependency. Cross-domain links navigate to their actual destination subject/island. Label aggregated island links as topic connections: one pair of related lessons does not make every lesson on one island a prerequisite for the other.

Use deterministic subject positions and a stable grid/radial/BFS arrangement inside focused clusters, without another layout dependency. Island aggregation can create reciprocal links/cycles even when the underlying concept graph is acyclic; never assume a DAG or recurse without a visited set. Render the active hierarchy level plus near scenery, not3895 simultaneous detailed leaf controls. Every lesson stays reachable through atlas → subject → island and through the complete List; no curriculum edge locks access. These semantics supersede a single long linear terrain-canvas plan.

## Implementation boundary

- One active branching map canvas with its own viewport; keep header, subject controls, zoom controls and lesson sheet outside its transform. List stays an unscaled accessible document with the same visual tokens, region hierarchy and selected stop styling.
- Start at scale1; clamp custom map zoom to1..2.5, preferably in0.25 button steps. Map stops therefore retain at least their existing44px tap target. Provide labelled Zoom in, Zoom out and Reset zoom controls; disable controls at actual bounds. Preserve browser/page zoom outside this canvas.
- Use top-left transform origin and bound horizontal pan to `[viewportWidth - canvasWidth * scale, 0]`. Reserve actual layout height equal to the unscaled canvas height times scale, measured with ResizeObserver. Do not leave transformed terrain overflowing an unchanged-height wrapper: that breaks scrolling, loading and return positions. Re-clamp after viewport resizing.
- Preserve native vertical scrolling and permit horizontal panning at baseline whenever the two-dimensional branching scene is wider than its viewport. Desktop drag may update panX and the owning surface's vertical scroll. A bounded2D viewport may use native overflow scrolling on both axes; avoid competing giant nested vertical surfaces, and persist whichever surface actually owns the position. Ordinary wheel and single-finger vertical scrolling remain native; intercept only canvas pinch/Ctrl-wheel/horizontal pan gestures that the map actually owns. Do not install global touch suppression, disable page zoom in viewport metadata or alter lesson-player gestures.
- Zoom around a content anchor: retain the content point under the pinch midpoint, pointer or viewport center when scale changes, adjusting panX and document scrollY after new layout height is applied. Reset on a late island must not jump to the beginning of the whole world.
- Preserve existing progressive island loading and lightweight geometry placeholders. Native IntersectionObserver may continue to use the browser viewport; transformed target bounds are the geometry it observes. Do not mount all SVGs because the user zoomed or entered immersive mode.
- Distinguish tap from drag/pinch with a small movement threshold; suppress only the click generated by a completed gesture. Keyboard activation and a later intentional tap must still select a lesson. Handle pointer/touch cancellation and lost capture without leaving a stuck drag state.
- Immersive mode is an in-app presentation toggle with a visible Exit control and Escape support, preserving the selected lesson and usable bottom sheet. Browser Fullscreen API is optional enhancement only; unsupported/denied calls must not block entry or exit. Retain an obvious exit at every responsive size.
- Extend the existing optional sessionStorage navigation snapshot with finite, clamped zoom/pan/immersive values, tolerant of older snapshots and storage failure. Restore map geometry before its saved scroll position. Explicit URL lesson selection still wins; Map/List and lesson-player return retain their existing semantics. This is navigation state, not learner progress; no new account/data synchronization or analytics.

## Bounded verification and landing

Use pure helper tests for clamp/anchor math, bounds after resize and malformed/legacy snapshot input. Browser checks should cover native scroll at100%, pinch and Ctrl-wheel anchored zoom, drag without accidental stop selection, stop tap at zoom, controls/keyboard/reset/Escape, late-subject lazy loading and exact lesson return with zoom/pan retained. Include phone, short phone and desktop screenshots for both Map and List, confirming no overlap with the fixed sheet and44px controls. Test pointer cancellation and a browser without Fullscreen API support if that API is used.
