## Decision for the reviewer: the static/chunks guard is narrower than the design note's literal "0 INTERNAL_STRINGS"

`tests/platform/built-output.test.mjs` (new W-946 test) does two things the design did not say:
1. **It skips chunks that only `/hq` pages reference.** It finds them from `server/app/hq/**/page_client-reference-manifest.js`, counting only chunks that no other manifest references, and it prints how many it skipped (12 on the applied build).
2. **The four field names `"owner"`, `"concept"`, `"objective"` and `"misconception"` get a ratchet** of at most 2 chunks, which is today's count, and the test prints those chunks. Every other `INTERNAL_STRINGS` entry (`checkedBy`, `checkedOn`, `Fact-checker to confirm`, `FACT-CHECK`, `FC pass`, `"builder"`, `company/reviews/`, `"curriculum"`, `"references"`, `"keyState"`, `"learner"`, `"interactions"`, `"pairwise"`) must have 0 hits.

Why: without these, the test fails on the applied tree for reasons that are not W-946 and that are outside this change. Weakening a guard is the risk O2 names, so **principal-engineer should accept, tighten or reject this explicitly.** The tighter alternatives are to move the Life Hacks specs out of client code (a content and template question for the Life Hacks owner, not platform's call), or to rename the label.

## 1. What can fail
- **A lesson does not render.** If a slug's loader were wrong, the feed or the lesson page would show "Unknown lesson" or a blank card. Invariant 4 in `check` blocks a wrong or missing loader. The contract and feed spec render each slug.
- **Build failure from `server-only`.** If any client module ever reaches `catalog.ts`, `next build` fails, which is loud and pre-deploy. Today no client module does (import scan, test 5).
- **CSS arrives after markup.** Each lesson's CSS now loads with its chunk instead of 751 sheets in the head. A card could flash unstyled on a slow network. I saw no flash on the 11 lessons in QA (loopback only). This is unmeasured on a real phone network (design note "would be wrong if").
- **"Loading…" while scrolling.** Each card's code is now fetched per card. The mitigation, if it shows: prefetch the next 2 cards' loaders in `Feed`.
- **Worst case:** a lesson shows another lesson's code, or a meta that is not its own, while `check` is green. Invariants 2 and 4 make this need a generator change that also beats the regexes (O6). Who sees it: learners.

## 2. How we would know
- `npm run check` (CI, verify) covers invariants 1 to 6 once the diff is applied.
- `npm run test:platform` covers the import scan (5 tests plus a self-check). It is now part of `npm run verify` (W-925 half: this branch adds it to `verify` before `check`). **CI does not run it.** `.github/workflows/ci.yml` (protected) runs check, typecheck, build and qa, not `verify` and not `test:platform`. So on CI, the importer guards (O2) are advisory until someone amends ci.yml. That would be a constitutional change and is not part of this one.
