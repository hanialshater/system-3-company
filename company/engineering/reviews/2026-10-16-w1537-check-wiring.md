## Part 1: W-1537 (commit 4430657)

**Change.** `package.json`: a new script `test:personalization` (`node company/personalization/model/self-check.mjs && node --test company/personalization/model/sim/privacy-n1-n3.test.mjs`), and `check` now ends `&& npm run test:personalization`. No dependency. `.github/workflows/ci.yml` (protected) is unchanged. Its `verify` job runs `npm run check`.

**Tier.** 1: a shared, reversible change to a gate script, and one revert undoes it. It needs no EDD and no readiness ceremony. This record is the "one reviewer reads the diff". Tier 2 would be ceremony.

### Measured (this worktree, Node v22.22.0)

- `npm run check` exits 0. The N1/N3 suite: 5 tests, 5 pass.
- Time: check without the new step (company + memory check) 0.31 s; `test:personalization` alone 0.92 s; full `check` 1.46 s. That is about 1 s added, so check takes about 4.5 times as long, but it is still under 1.5 s.
- **This worktree has no `node_modules`, and check still passes.** Today `check` needs no `npm ci`. That property matters (see "Rejected" below).
- CI: `ci.yml` line 49 sets `actions/setup-node@v4` `node-version: 22`, a floating major. setup-node resolves it to the newest 22.x it has (≥ 22.18 today, since 22.18 shipped in July 2025). So CI runs the `.ts` files with type stripping on by default. `deploy.yml` uses `"22"` but does not run check.
- Pins: `package.json` `engines` says `"node": ">=20"`. There is no `.nvmrc` and no `.node-version`. **The declared floor is now false for `check`.** On Node 20, or 22.0 to 22.17, `check` will fail on `import "./model.ts"` with `ERR_UNKNOWN_FILE_EXTENSION`, and nothing in the output says the cause is the Node version.

### Findings (problems, not fixes)

1. **check vs verify: check is the right place, for a reason the commit did not state.** Every other `test:*` script runs only in `verify`, but CI does not run `verify`. Its verify job runs `check`, `typecheck`, `build` and `qa`, so `test:hq`, `test:kit` and the rest never run in CI. Without a ratified ci.yml amendment, `check` is the only place that makes T1 an enforced gate rather than a habit. A ~1 s cost on a gate every role runs is acceptable. The exception to the "tests live in verify" convention is deliberate. It should be written down where the next engineer will look (C3).
2. **Node floor (medium likelihood locally, low in CI).** A role session on an older local Node gets a red `check` with a cryptic module error and may "fix" it by removing the step. `engines: >=20` invites exactly that Node.
3. **Blast radius.** A model change that breaks an invariant, a `MODEL_VERSION` bump without its decision line, or any `src/` file that imports the model folder now fails everyone's `check`. On `main` that is the intended behaviour: the privacy ruling is a gate, and the boundary scan exists to catch other roles' `src/` edits. The cost is that an unrelated role sees a FAIL line naming model internals and may not know whose it is. The failure lines (`self-check.mjs` "FAIL (n): …") do not name the owner or the fix path.
4. Not a finding: `&&` chaining means a personalization failure hides nothing earlier, because company and memory checks run first.

### Rejected options (two options and doing nothing)

- *Verify only:* does not reach CI (finding 1). Rejected.
- *Run through the repo's TS loader (`--import ./tests/lifehacks/register.mjs`) for Node 20 support:* I tried it, and it needs `typescript` from `node_modules`, which would make `check` depend on `npm ci` for every role. That is worse than a Node floor. Rejected.
- *Do nothing:* T1 stays "passes when run" (privacy ruling §1 T1). Rejected.

### Decision: **approve with conditions**

- **C1 (before merge, learner-model-engineer):** fail fast and clearly on an old Node. `test:personalization` (or the first lines of `self-check.mjs`) prints `test:personalization needs Node >= 22.18 (have vX)` and exits 1 when `process.versions.node` is lower. Do not skip silently: a skip would turn T1 back into a habit.
- **C2 (before merge, learner-model-engineer):** set `package.json` `engines.node` to `">=22.18"` so the declared floor matches what `check` now needs. Optionally add a `.nvmrc` with `22`. Neither is protected and neither changes CI.
- **C3 (before merge, one line):** add a comment line in `company/personalization/model/sim/README.md` (already edited in this commit), or next to the script, saying why this test is in `check` and not `verify` (finding 1), so nobody "tidies" it into verify.
- **C4 (follow-up, not blocking):** make the self-check FAIL line name the owner (`learner-model-engineer`) and the README section to read. That is the blast-radius mitigation for finding 3.
- **Objection that travels:** if `check` gains more slow suites this way, it stops being the fast tier-0 gate. Budget: `check` stays under 3 s on the dev host. Past that, the remedy is an amendment that adds a CI step for `verify`'s `test:*`, not more growth of `check`.

This verdict does not cover that part. Board: W-1498 stays open with a note. If the founder's Q2 answer means new `meta.json` fields, that part needs an EDD.
